# v0.140.2 — Hot-Path Lock Fix (VAL-374)

## Theme

`pg_ripple.infer()` no longer takes `ACCESS EXCLUSIVE` on
`_pg_ripple.predicates` on every call: `datalog::ensure_catalog()` probes the
catalog first and only emits DDL when something is actually missing.

## Problem

`ensure_catalog()` runs in **every** `pg_ripple.infer()` (hot path of the
engine write path, `src/kg-ripple.ts`) and executed DDL unconditionally:

- `CREATE TABLE IF NOT EXISTS _pg_ripple.rules`
- `CREATE TABLE IF NOT EXISTS _pg_ripple.rule_sets`
- `ALTER TABLE _pg_ripple.predicates ADD COLUMN IF NOT EXISTS derived …, rule_set …`

`ALTER TABLE` acquires **`ACCESS EXCLUSIVE` on `_pg_ripple.predicates`** even
when the columns already exist, and `CREATE TABLE IF NOT EXISTS` locks the
existing relation. Result: ANY session holding `ACCESS SHARE` over the catalog
(any SELECT on the catalog in a long transaction — psql analytics, GC, 
backfill) blocked the whole KG write path until it committed. Production
incident 04/10 09:08-09:11 (holder `valorbrain:kg-maint`, `infer` cancelled at
174 s by the monitor); reproduced in isolation on a disposable 0.140.0
cluster during the VAL-372 forensics (`Lock/relation`, `blocked_by` the
`AccessShareLock` session).

## Fix

- Catalog probe before any DDL: `to_regclass` for `rules` / `rule_sets`,
  `pg_attribute` for the `rules.name` column, `pg_class` for the
  `uq_rules_set_name` index, and `pg_attribute` for the `predicates.derived`
  / `predicates.rule_set` columns — the same guard shape the VAL-208 block
  inside `ensure_catalog()` already used, hoisted to gate the whole function.
- When the catalog is complete the function returns immediately: zero DDL,
  zero exclusive locks, zero catalog-invalidation noise on the hot path.
- The DDL path is unchanged and still runs on first bootstrap and on
  pre-0.131.0 upgrades missing `rules.name` or the unique index (probe fails
  → fall through).
- A failed probe (e.g. permissions) warns and falls through to the DDL path,
  which surfaces the real error exactly as before — no new failure mode.

## Out of Scope (follow-up)

- `construct_rules::catalog::ensure_catalog()` (and `rule_library`'s) have the
  same unconditional-DDL shape, but they are NOT on the `infer()` hot path —
  they run lazily on first use of their own APIs. Same probe treatment can be
  applied when those paths show up in production contention.
- The engine-side GC scan that held `ACCESS SHARE` for minutes was already
  fixed in agentxagi/valorbrain#284 (211 s → 1.7 s); the two fixes together
  close the VAL-372 incident family.
